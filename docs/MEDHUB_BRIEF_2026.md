# MedHub — Продуктовый бриф для разработки
### Версия 1.0 | Март 2026

---

## 1. Суть продукта

MedHub — AI-агент медицинского сопровождения с рабочей средой.

Не медицинский сайт с AI-вкладкой. Агент — центр продукта. Интерфейс — его рабочая среда.

Пользователь не ищет AI внутри продукта. Агент встречает пользователя, ведёт его, объясняет что делать, удерживает контекст и сопровождает на каждом шагу.

**Главный критерий любого решения:**
Усиливает ли это ощущение живого сопровождения агентом? Если нет — вторично.

**Регуляторный периметр:**
Продукт позиционируется как "wellness companion / health information". Агент не ставит диагнозы — он строит гипотезы, находит корреляции и помогает прийти к врачу с конкретным вопросом.

**Тон везде — "ты".** Не "вы". Это принципиально для эмоциональной близости.

## 3. Визуальная система

**Тема:** тёплый тёмный. Весь продукт — тёмный, без разрывов.

**Палитра:**
- Фон: `#0d1117`
- Карточки/поверхности: `#161b22`
- Акцент: `#2dd4bf` (teal)
- Важные моменты: `#f59e0b` (amber — не красный)
- Основной текст: `#e6edf3`
- Muted текст: `#7d8590`
- Glow: `box-shadow: 0 0 20px rgba(45, 212, 191, 0.12)`

**Никогда не использовать красный** для тревожных данных — вызывает панику. Вместо красного — amber.

**Анимации:**
- Spring physics (Framer Motion) для всех переходов
- Typing animation для сообщений агента
- Ambient breathing для фоновых элементов
- Staggered reveal при загрузке карточек

## 4. Центральная визуальная концепция — "Карта здоровья"

Не разделы. Картина.

Пользователь заходит и видит единую живую карту своего здоровья. Всё связано. Видно как одно влияет на другое. **Карта = навигация.** Тапнул узел — провалился в раздел.

**Узлы карты:**
- Самочувствие (дневник + эмоции)
- Цифры (показатели)
- Документы
- Лекарства
- Симптомы
- Образ жизни

**Линии между узлами** = корреляции которые нашёл агент.
Линия появляется когда агент нашёл связь. Пульсирует когда связь активная.
Нажал на линию — агент объясняет что связано и как.

**Состояния узлов:**
- Тусклый серый = нет данных
- Teal свечение = данные есть, агент работает
- Amber пульсация = агент хочет что-то показать

**Пустая карта = мотивация.**
Новый пользователь видит несколько тусклых узлов без линий.
Агент: "Это твоя карта здоровья. Пока она почти пустая — я мало что вижу. Давай заполним её вместе."

**Главное правило:** каждый элемент карты тестируется одним вопросом: "Человек без контекста поймёт что это и зачем за 3 секунды?"

**Технически:** кастомный SVG/Canvas + Framer Motion. Линии появляются на основе MCO (поле correlations).

## 5. Архитектура AI — три слоя

Пользователь видит одного агента. Под капотом — три уровня.

### Скрипт с ротацией (бесплатно)
Всё что не зависит от конкретных данных пользователя:
- Приветствия (пул 5-7 шаблонов, выбор по MCO, ротация без повторов)
- Статусы карточек на dashboard
- Подсказки (?) везде
- Capability unlock сообщения
- Nudge-сообщения
- Первый вход в раздел
- Подтверждения действий

**Template rotation:** для каждого контекста пул из 5-7 шаблонов. Последние 3 использованных не повторяются. Haiku чуть перефразирует финальный текст — даже один шаблон никогда не даёт дословно одинаковую фразу.

### Claude Haiku (быстро, дёшево)
Только когда есть что сказать именно этому пользователю именно сейчас:
- Diary: реакция на запись после сохранения (2-3 фразы именно на написанное)
- Vitals: короткий комментарий после ввода показателя
- Чат: лёгкие вопросы, навигация, "как дела?"

### Claude Sonnet (глубокий анализ, только по запросу)
- Чат: медицинские вопросы, корреляции, гипотезы
- Документы: разбор по явному запросу пользователя
- Подготовка к врачу
- Weekly insight (batch, фоновый, воскресенье ночью)

**Sonnet живёт в чате, не в модулях.**

## 6. MCO — Medical Context Object

Единый "мозг агента". Хранится в Supabase. Читается во всех разделах.

```json
{
  "entry_mode": "diagnosis",
  "name": "Алексей",
  "current_focus": "гипертония, слежу за давлением",
  "last_seen": "2026-03-25T19:42",
  "days_absent": 2,
  "time_of_day": "morning",
  "data_completeness": {
    "vitals": 0.7,
    "diary": 0.2,
    "documents": 0.5,
    "medications": 1.0,
    "symptoms": 0.3
  },
  "recent_patterns": [
    "давление выше по утрам 4 дня подряд"
  ],
  "open_questions": ["не сдан общий анализ крови"],
  "pending_nudges": ["спросить про головные боли"],
  "correlations": [
    {"from": "vitals", "to": "diary", "description": "давление выше в дни с коротким сном"}
  ],
  "greeting_context": "returned_after_absence",
  "priority_action": "add_vitals",
  "last_used_templates": ["t3", "t1"],
  "updated_at": "2026-03-25"
}
```

**Правила MCO:**
- Append-only. Никогда не редактировать прошлые записи.
- Обновляется фоновым Edge Function после значимых событий.
- Кешируется в Supabase, пересчитывается если старше 30 минут.

## 8. Первый вход в продукт (guided tour)

Только для новых пользователей, один раз.

1. Агент говорит: "Давай покажу где всё находится — займёт минуту." Кнопка "Покажи".
2. Overlay-тур: подсвечивается один элемент, агент объясняет в 1-2 фразах. 5-6 остановок — только самое важное.
3. После тура агент говорит первое что нужно сделать.

Везде постоянные подсказки (?) — можно вернуться к объяснению любого блока в любой момент.

## 9. Dashboard — главный экран

**Три зоны:**

**Верхняя — агент.** Хозяин экрана, не виджет. Приветствие с template rotation + typing animation.

Варианты приветствий по контексту:
- Первый вход: "Алексей, я на месте. Первая точка данных — и я начну собирать твою линию."
- Возврат через 2-3 дня: "Тебя не было 2 дня. Я держал картину пока тебя не было."
- Агент нашёл паттерн: "Алексей, я заметил кое-что. Давление и сон — похоже есть связь."
- Вечер: "Как прошёл день? Пара строк в дневнике — и я буду видеть сегодняшнюю картину."

**Средняя — карточки разделов.** Каждая карточка = живой статус от агента + иконка (?).
- Самочувствие: "последняя запись вчера"
- Цифры: "не вносилось 3 дня"
- Документы: "1 не разобран"
- Лекарства: "всё в порядке"
- Симптомы: "нет данных"

Тапаешь карточку — проваливаешься в раздел.

**Нижняя — одно приоритетное действие** от агента. Детерминированная логика по MCO.

**Навигация:** нижняя панель 5 разделов (названия уточнить после первого прототипа).

## 10. Присутствие агента — три формата

**Формат 1 — Подсказки (?) везде, скрипт**

Каждый раздел, поле, блок имеет иконку (?). Агент объясняет от первого лица.

Примеры:
- Дневник: "Это твой ежедневный журнал самочувствия. Пара строк в день — и через неделю я начну видеть закономерности которые ты сам можешь не замечать."
- Цифры: "Здесь живут твои цифры. Каждое измерение — точка на твоей линии. Чем больше точек — тем яснее куда линия движется."
- Симптомы: "Отмечай где и что беспокоит. Я смотрю не на отдельные симптомы — а на то как они связаны с остальными данными."
- Лекарства: "Добавь препараты — я буду учитывать их при анализе. Иногда связь между лекарством и состоянием не очевидна. Я её замечу."
- Документы: "Загружай сюда всё — анализы, заключения, выписки. Я читаю их и вытаскиваю главное."

**Формат 2 — Sidebar-реплики, скрипт с ротацией**

Только при наличии повода:
- Первый вход в раздел -> агент объясняет зачем это нужно
- Не заходил в раздел 5+ дней -> тихий nudge
- Добавил первую запись -> агент реагирует

**Формат 3 — Capability unlock, скрипт с ротацией**

- После первой записи в дневник: "Первая точка есть. Продолжай — через 7 дней я покажу тебе первый паттерн."
- После 7 дней дневника: "Неделя есть. Я вижу кое-что интересное. Хочешь покажу?"
- После первого показателя: "Теперь я вижу цифры. Добавляй регулярно — появится линия."
- После первого документа: "Я прочитал документ. Теперь у меня есть медицинский контекст — мои наблюдения станут точнее."
- После 3+ разделов: "Картина начинает складываться. Я уже вижу связи. Продолжай — дальше интереснее."

## 11. Модули

### Самочувствие — "Пульс" (diary + emotions)

Ввод — три шага:
1. Быстрое состояние: 5 иконок (тяжело / так себе / норм / хорошо / отлично). Тапаешь — загорается teal.
2. Энергия: горизонтальный слайдер, заполняется teal.
3. Свободный текст: тёмное поле, мигающий курсор, никаких лейблов.

Сохранение: запись с анимацией "падает" в календарь. Агент реагирует через Haiku — 2-3 фразы именно на написанное.

Визуализация истории: 30-дневный календарь. Через заполненные ячейки — волнистая пульс-линия. Высота волны = энергия. Где дней нет — линия обрывается. Разрыв некомфортен — хочется заполнить.

### Цифры — "Линия" (vitals)

Ввод: большие цифровые поля, цифровая клавиатура сразу. Добавил — значение ложится на график с анимацией.

Визуализация: линия рождается с первой точкой. Пока пусто — пунктир + "жду первое измерение".
Поверх линии — полупрозрачная полоса нормы (confidence band). Внутри = teal. За полосой = amber.

Агент после ввода (Haiku): "чуть выше вчерашнего, но в норме" / "третий раз за неделю выше 140 — я отмечаю".

### Симптомы — "Сигналы"

Ввод: body map только как инструмент указания зоны -> выбрать симптом -> сохранить. Никакой подсветки "больных зон".

Визуализация: частотная карта. Каждый симптом = строка + визуальная плотность за 30 дней.

Агент: смотрит на частоту и связи. "Головная боль появляется в дни с коротким сном — я вижу эту связь 6 раз за месяц."

### Лекарства — "Режим"

Ввод один раз: название, дозировка, расписание.

Визуализация: каждое лекарство = карточка с пульсом. Принято = teal. Пропущено = amber + nudge от агента.

Агент следит за регулярностью и ищет корреляции с симптомами и показателями.

### Документы — "Библиотека"

Визуализация: визуальные слоты по типам (анализ крови, МРТ, выписка, направление, рецепт). Пустой слот = подпись агента "я его ещё не видел".

Механика: загрузил -> скрипт подтверждает -> агент спрашивает "разобрать?" -> да = Sonnet читает и выдаёт три вещи: что увидел, что важно, что делать дальше.

### Врач — "Брифинг"

Пользователь нажимает "Готовлюсь к врачу" -> выбирает специальность -> Sonnet собирает брифинг из всего MCO: показатели, симптомы, лекарства, вопросы к врачу.

Визуализация: брифинг "собирается" анимированно — видно как агент подтягивает данные из узлов карты.

На выходе: чистый документ для врача.

### Чат — "Разговор"

Агент говорит как человек который знает всю карту: "Я смотрю на твою карту и вижу..."

Suggested questions меняются каждый день на основе MCO — конкретные, не шаблонные.

Роутер: лёгкий вопрос -> Haiku. Анализ / корреляция / гипотеза -> Sonnet. Пользователь не знает какая модель.

### Хронология — "Река"

Все события на одной визуальной оси времени. Плотность видна сразу.
Цвета по типу: показатели = teal, дневник = фиолетовый, документы = amber, симптомы = приглушённый красный.

Агент выделяет значимые периоды. Нажимаешь — видишь что происходило.

## 12. Рабочая модель агента

**Главная ценность:** пользователь знает симптомы. Агент знает паттерны. Ценность = агент соединяет одно с другим, называет это вслух.

**Структура гипотезы:**
1. Что вижу (данные + паттерн)
2. Что это может значить (гипотеза с названием состояния)
3. Что проверить (конкретный следующий шаг)

**Как называть состояния:**
Агент называет прямо — это экспертность. Но формулировка отделяет наблюдение от диагноза.

Bad: "У тебя гипертония"
Good: "Сочетание которое я вижу — повышенное давление по утрам, головные боли, нарушения сна — это классические признаки, которые врачи связывают с гипертонией 1 степени. Я не ставлю диагноз — это может подтвердить только врач. Но вектор понятен, и идти нужно к кардиологу."

Ключевая формулировка: "врачи связывают с [состояние]" — не "у тебя [состояние]".
Всегда называть специальность врача.

**Шкала срочности:**
- Низкая: "Заметил совпадение. Наблюдаем."
- Средняя: "Три признака указывают в одну сторону. Стоит проверить."
- Высокая: "Это классическая картина для [состояние]. Нужно обсудить с врачом как приоритет."

**Что агент не делает:**
- Не говорит "сходи к врачу" без конкретики
- Не уклоняется от называния состояния
- Не даёт указаний по приёму лекарств
- Не говорит общими фразами когда есть данные

## 15. Рабочая логика разработки

1. Фиксируется текущая продуктовая точка
2. Выбирается один приоритет
3. Формулируется один узкий шаг
4. Задача ставится Claude Code
5. Verdict: ACCEPTED / NOT ACCEPTED + точечные правки
6. Новые ветки не открываются пока текущая не закрыта
